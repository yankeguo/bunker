# AGENTS.md

Guidance for coding agents working on this repository.

## Project Overview

bunker is a simple bastion (jump host) system for Linux servers. It consists of:

- A Go backend (`*.go` in the repo root, package `bunker`) providing an HTTP API, an SSH
  proxy server, and embedded static UI serving.
- A Nuxt 3 web UI (`ui/`), statically generated and embedded into the Go binary.

Users upload SSH public keys in the web UI; admins register target servers and create
grants (wildmatch patterns on `server_user` and `server_id`). Users then connect with
`ssh server_user@server_id@<bunker-host> -p 8022`; bunker authenticates them by public
key and pipes the session to the target server using its own client keys (see
`signers.go`, `ssh.go`).

## Repository Layout

- `cmd/bunker/main.go` — entrypoint, wires everything with `go.uber.org/fx`
- `app.go` — HTTP API routes (under `/backend/...`)
- `ssh.go` — SSH bastion server and session piping
- `signers.go` — host/client SSH key generation and loading (stored in the data dir)
- `database.go` — SQLite (gorm, pure-Go driver `glebarez/sqlite`, WAL + busy timeout)
  setup and `users.yaml` seeding
- `static.go` — embeds `ui/.output/public`, serves it with a `404.html` fallback;
  proxies to `localhost:3000` when `DEBUG=ui`
- `options.go` — `DataDir` type and `DEBUG` env parsing
- `ratelimit.go` — in-memory failure rate limiter used by sign-in
- `model/` — gorm models; `model/dao/` — generated by gorm gen, do not edit by hand
- `scripts/create-dao/` — regenerates `model/dao` (run `go run ./scripts/create-dao`
  after changing models; it creates a throwaway `database.sqlite3` in the repo root,
  which is gitignored)
- `ui/` — Nuxt 3 app (`@nuxt/ui` v2, npm)

## Build & Test

```bash
# UI first (required — static.go embeds ui/.output/public)
cd ui && npm ci && npm run generate && cd ..

# Backend
go build ./...          # or: go build -o bunker ./cmd/bunker
go vet ./...
```

There are no tests in this project; verify changes with `go build`, `go vet`, and a
smoke run:

```bash
mkdir -p /tmp/data
printf 'server:\n  listen: ":18080"\nssh_server:\n  listen: ":18022"\n' > /tmp/data/config.yaml
./bunker --data-dir /tmp/data
# then check http://127.0.0.1:18080/ and `ssh -p 18022 x@y@127.0.0.1` (banner proves SSH is up)
```

Docker: `docker build .` — but the UI must be generated into `ui/.output/public` first
(CI does this; `.dockerignore` does not exclude it).

## Dependency Notes

- `github.com/yankeguo/ufx` (v0.2.5, unmaintained upstream) uses
  `otelhttp.DefaultClient` and `otelhttp.WithRouteTag`, which were removed in
  `go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp` v0.65.0. Keep
  otelhttp pinned at **v0.64.0** (and otel at the matching v1.39.x) unless ufx is
  replaced.
- UI dependencies are intentionally kept on their current majors: Nuxt 3 + `@nuxt/ui`
  v2. Upgrading to Nuxt 4 / `@nuxt/ui` v3+ is a breaking rewrite of the components.
- npm gates dependency install scripts; `esbuild`'s postinstall is approved via the
  `allowScripts` field in `ui/package.json`. Don't remove it.

## Configuration

Runtime config is a `config.yaml` in the data dir (`--data-dir` flag):

```yaml
ui: # display only
  ssh_host: "my.fancy.domain"
  ssh_port: "8022"
server:
  listen: ":8080"
  # trust X-Forwarded-For / X-Forwarded-Proto from a front reverse proxy
  trust_proxy: false
ssh_server:
  listen: ":8022"
```

`users.yaml` in the same dir seeds initial users (see README.md). SSH host/client keys
are auto-generated into the data dir on first run.

## Conventions

- Error handling in HTTP handlers uses `rg.Must*` (panic-on-error) and `halt` for
  client errors; keep that style.
- Database access goes through the generated `dao` package, not raw gorm calls.
- `ufx.Context.Bind` only binds fields; it does **not** run `validate` tags (only
  `ufx.Conf.Bind` does), so validate request fields explicitly in handlers.
- State-changing endpoints are wrapped with `post(...)` in `app.go`; they must be
  called with POST and never perform side effects on GET.
- Use conventional commit messages.
